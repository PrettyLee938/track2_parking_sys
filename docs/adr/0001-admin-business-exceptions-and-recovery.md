# Admin business exceptions and run recovery

We allow an authenticated Admin to authorize a one-session unpaid departure as an explicit business exception after password re-entry, a reason, and confirmation. Equipment and occupancy restrictions remain enforced for every role; the exception preserves unpaid truth and is consumed only on confirmed departure. Pending authorizations survive a backend restart only after the same run, session, and car are reconciled. Ambiguous run identity pauses automation until an Admin chooses to continue or start a new run; new runs make prior state read-only and never carry reservations or payment state forward. This boundary is deliberate because a flexible business override is useful during operations, while bypassing physical interlocks or guessing across a simulator reset would create penalties and corrupt the audit trail.
